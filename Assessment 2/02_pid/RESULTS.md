# 02 Pole-placement discrete PID - RESULTS

Generated by `pid_main.m` (sampling time T = 0.02 s everywhere; every number below is printed by the script). Octave 8.4 run, code written for MATLAB R2026a compatibility (no local functions in scripts).

Summary: two analytic pole-placement PIDs (longitudinal position loop, lateral cross-track loop) with a filtered derivative, back-calculation anti-windup, a zero-cancelling reference prefilter (2-DOF) and speed scheduling of the lateral gains. All targets (zeta >= 0.7, t_ss <= 2.5 s, OS < 10 %) are met on the full-order identified models and on the non-linear plant.

## 1. Design plants (discretisation stated exactly)

Identified models (01_sysid/RESULTS.md): `Gv(z) = b/(z - a)`, a = 0.911883, b = 0.088206 (v_cmd -> v, DC gain 1.0010); `Gr(z) = br z^-3 / (1 + a1 z^-1 + a2 z^-2) = br / (z (z^2 + a1 z + a2))`, br = 0.292266, a1 = -1.312195, a2 = 0.481324 (u_lat -> yaw rate r, DC gain k_delta = 1.7281).

**Longitudinal loop** (output s = along-track position, control v_cmd). Speed is integrated with forward Euler, `s(k+1) = s(k) + T v(k)`, i.e. `T/(z-1)`:
```
Gs(z) = Gv(z) T/(z-1) = b T / ((z - a)(z - 1))        (order 2, exact; type 1)
```
**Lateral loop** (output e_y = cross-track error, left positive; control u_lat = yaw-rate demand). Linearised path following at design speed **v0 = 2.0 m/s**: `psi_e(k+1) = psi_e(k) + T r(k)`, `e_y(k+1) = e_y(k) + T v0 psi_e(k)` (forward Euler):
```
G_ey(z) = v0 T^2 Gr(z)/(z-1)^2 = v0 T^2 br / ( z (z^2 + a1 z + a2) (z-1)^2 )   (order 5, 3-sample delay, type 2)
```
The PID error is e = e_ref - e_y, so the plant gain is positive in both loops. The **full-order** plants are used for the design and for all verifications (no model reduction in the final design; see Section 4.3 for what a reduction would cost).

## 2. Discrete PID: exact form

Parallel form, backward-Euler integrator, filtered backward-difference derivative (one extra parameter N, `pf = 1/(1 + N T)` = pole of the derivative filter; `D(k)` is the backward-Euler discretisation of `Kd s/(1 + s/N)`):
```
I(k)  = I(k-1) + Ki T e(k)
D(k)  = pf D(k-1) + Kd (1 - pf)/T * (e(k) - e(k-1))
u(k)  = Kp e(k) + I(k) + D(k)                      (before saturation; implemented in pid_step.m)
C(z)  = Kp + Ki T z/(z-1) + Kdf (z-1)/(z-pf) = Nc(z) / ((z-1)(z-pf)),   Kdf := Kd (1-pf)/T
Nc(z) = c2 z^2 + c1 z + c0,
  c2 = Kp + Ki T + Kdf,   c1 = -[(1+pf) Kp + pf Ki T + 2 Kdf],   c0 = pf Kp + Kdf
```
With pf = 0 this is the textbook `Kp + Ki T z/(z-1) + Kd (z-1)/(T z)`. The four free parameters are (Kp, Ki, Kd, pf) <-> (c2, c1, c0, pf).

**Why the lateral extra poles are only 2x (not 4-5x) faster.** The path-following plant has two integrators, a 3-sample delay and a lightly damped 2nd-order lag (wn = 24.7 rad/s). Solving the linear Diophantine system for faster extra poles (kappa >= 3) returns pf > 1 - an unrealisable, unstable derivative filter - whereas for the longitudinal plant (order 2, no residual poles) kappa = 4 is fine. ## 4. Characteristic polynomial and coefficient matching

### 4.1 Closed-loop polynomial
```
plant G = Np(z)/Dp(z),  Dp monic of degree n (n = 2 lon, n = 5 lat),  Np = const (lon: b T; lat: v0 T^2 br)
1 + C G = 0  <=>  Delta(z) = (z-1)(z-pf) Dp(z) + Nc(z) Np(z) = 0,       degree n+2
Delta(1) = Nc(1) Np(1)   (Dc(1) = 0)
```
### 4.2 Longitudinal loop (n = 2): symbolic derivation, exact 4x4 matching
With `Dp = z^2 + p1 z + p0`, `p1 = -(1+a)`, `p0 = a`, `n0 = b T` and the desired polynomial `Ad(z) = prod (z - z_i) = z^4 + e3 z^3 + e2 z^2 + e1 z + e0`:
```
(z-1)(z-pf)(z^2 + p1 z + p0)  =  z^4 + [p1 - (1+pf)] z^3 + [p0 - (1+pf) p1 + pf] z^2 + [pf p1 - (1+pf) p0] z + pf p0
Delta(z) = that + n0 (c2 z^2 + c1 z + c0)
matching with Ad(z):
  z^3 :  p1 - 1 - pf               = e3     =>  pf = p1 - 1 - e3 = sum(z_i) - 2 - a
  z^2 :  p0 - (1+pf) p1 + pf + n0 c2 = e2   =>  c2 = [e2 - p0 + (1+pf) p1 - pf]/n0
  z^1 :  pf p1 - (1+pf) p0 + n0 c1   = e1   =>  c1 = [e1 - pf p1 + (1+pf) p0]/n0
  z^0 :  pf p0 + n0 c0               = e0   =>  c0 = [e0 - pf p0]/n0
```
The PID gains follow from the linear 3x3 system (det = -(1-pf)^2 != 0):
```
[ 1     1    1 ] [Kp  ]   [ c2 ]
[1+pf  pf   2 ] [Ki T] = [-c1 ]            =>   Kp  = [-c1 - pf c2 - (2-pf) c0]/(1-pf)^2
[ pf    0    1 ] [Kdf ]   [ c0 ]                 Kdf = c0 - pf Kp,   Ki T = c2 - c0 - (1-pf) Kp,   Kd = Kdf T/(1-pf)
```
Numbers (lon): Ad = z^4 -3.510866 z^3 +4.613546 z^2 -2.689189 z +0.586646; p1 = -1.911883, p0 = 0.911883, n0 = 0.001764 -> pf = 0.598983, Nc = [25.85542 -48.70301 22.92569]. Closed-form formulas vs generic Diophantine solver: max difference 1.5e-11 (3x3 solve check 2.0e-14).

The correctness of the expansion is checked numerically in the script: all four desired poles are roots of `Delta(z)` built by polynomial multiplication (max distance in Section 6), and the poles of `feedback(C G, 1)` from the Control System Toolbox agree (difference printed in Section 6).

### 4.3 Lateral loop (n = 5): Diophantine equation on the FULL model
A 3-parameter (4 with the filter) PID cannot place all n+2 = 7 poles of the full path-following model. Instead of discarding dynamics, the **dominant pair and the two extra real poles are placed exactly on the full model** and the remaining n-2 = 3 poles are the roots of an unknown monic residual polynomial R(z):
```
(z-1)(z-pf) Dp(z) + Nc(z) Np  =  Ad(z) R(z),     R(z) = z^3 + r2 z^2 + r1 z + r0
<=>  z(z-1) Dp(z) + pf (1-z) Dp(z) + (c2 z^2 + c1 z + c0) Np = Ad(z)(z^3 + r2 z^2 + r1 z + r0)     [(z-1)(z-pf) = z(z-1) + pf(1-z)]
```
Delta is affine in (pf, c2, c1, c0) and R is affine in (r2, r1, r0), so matching the n+2 = 7 non-leading coefficients is a **square linear system** `A x = b`, `x = [pf c2 c1 c0 r0 r1 r2]^T` (`pid_diophantine.m`; for n = 2 it degenerates to the equations of 4.2). Gains follow from the same closed form as in 4.2.
Numbers (lat): residual |A x - b| = 2.5e-16, cond(A) = 4.1e+06; pf = 0.234535; Nc = [42.20667 -82.77006 40.59117]; residual polynomial roots (poles NOT assigned, all verified inside the unit circle): 0.41790+0.20505i, 0.41790-0.20505i, -0.05568+0.00000i, (these are fast: |z| <= 0.47, i.e. >= 38 rad/s).

**Why not the static reduction?** The assignment hint (reduce Gr to its DC behaviour k_delta, place the poles on `k_delta v0 T^2/(z-1)^2` by exact matching with `pid_coeffmatch.m`) was implemented and tested on the full model with the same desired poles:
| design | Kp | Ki | Kd | pf | full-model max abs(pole) | min zeta of all poles | zeta_dom | t_ss prefilter [s] |
|---|---|---|---|---|---|---|---|---|
| static reduction (DC gain only) | 2.497 | 2.504 | 1.076 | 0.767 | 0.9819 | 0.20 | 0.20 | 2.94 |
| **Diophantine on full model (used)** | 2.063 | 1.815 | 1.048 | 0.235 | 0.9608 | 0.68 | 0.75 | 2.10 |

The neglected 0.1 s equivalent delay (3-sample delay + servo lag) collapses the damping of the dominant pole pair from the designed 0.75 to 0.20 with the reduced-model gains; hence the reduction was rejected and the exact full-order placement is used.

Achieved closed-loop poles (roots of Delta, full order; lon: 4, lat: 7):

- lon: 0.94755+0.03133i, 0.94755-0.03133i, 0.80789+0.00000i, 0.80789-0.00000i,
- lat: 0.96019+0.03389i, 0.96019-0.03389i, 0.92312+0.00000i, 0.92312-0.00000i, 0.41790+0.20505i, 0.41790-0.20505i, -0.05568+0.00000i,

Maximum distance desired -> achieved pole: lon 1.9e-07, lat 1.2e-06 (numerical root sensitivity of double poles, ~sqrt(eps)); Control System Toolbox cross-check `pole(feedback(C*G,1))`: lon 0.0e+00, lat 0.0e+00 (NaN = toolbox absent). Dominant achieved poles: lon s = -2.667 +1.653i 1/s -> zeta = 0.8500, wn = 3.1373 rad/s; lat s = -2.000 +1.764i 1/s -> zeta = 0.7500, wn = 2.6667 rad/s.

**Zero problem and its fix.** A PID has two zeros (roots of Nc). In a 1-DOF loop they produce a large overshoot even though the poles are well damped:
| loop | OS 1-DOF [%] | rise 10-90 % [s] | t_ss 1-DOF [s] |
|---|---|---|---|
| lon | 22.4 | 0.200 | 1.52 |
| lat | 64.3 | 0.180 | 2.94 |

Fix (pole placement with zero cancellation, 2-DOF): reference prefilter `F(z) = Nc(1) z^2 / Nc(z)` (`pid_prefilt.m`; the poles of F are the PID zeros listed above, all inside the unit circle, DC gain 1, implemented as `c2 rf(k) = Nc(1) r(k) - c1 rf(k-1) - c0 rf(k-2)`). The reference transfer function becomes
```
T_r(z) = F(z) Nc(z) Np / Delta(z) = Nc(1) Np z^2 / ( Ad(z) R(z) )       (T_r(1) = 1; no zero other than z = 0)
```
so the step response is governed by the placed poles only. The feedback path (disturbance rejection, ramp tracking) is unchanged. The prefilter is used for reference steps (the metrics below); for a smoothly moving reference (navigation) the plain 1-DOF loop plus feedforward is used.
Check of the derivation: the closed-form T_r(z) above, evaluated with `filter`, agrees with the step response of the simulated difference equations (plant + `pid_step` + `pid_prefilt`) to 2.3e-12 (lon) and 4.1e-11 (lat).

## 7. Saturation and anti-windup

Limits: longitudinal `0 <= v_cmd <= 3.0 m/s`; lateral `|delta| <= 0.34 rad`, mapped to a speed-dependent `|u_lat| <= lat_input(v, delta_max)` (`pid_ulat_limit.m`; 1.479 rad/s at v = 2 m/s, 0.86 at 1 m/s, 1.81 at 3 m/s). The feedforward is added *before* the limiter so the anti-windup acts on the total command.

Implemented in `pid_step.m` (selectable, `g.aw`):
```
u_un = uff + Kp e + I(k-1) + Ki T e + D;   u = sat(u_un, umin, umax)
aw = 1 (default) back-calculation:  I(k) = I(k-1) + Ki T e(k) + T Kt (u - u_un),   Kt = 1/Tt = 1/sqrt(Ti Td)
aw = 2 conditional integration:     I(k) = I(k-1) if (u_un > umax and e > 0) or (u_un < umin and e < 0), else I(k-1) + Ki T e
aw = 0 none
```
In the unsaturated regime u = u_un exactly, so the linear design is untouched. Demonstration with large steps (1-DOF, no prefilter, `fig/fig_antiwindup.png`):

| test | anti-windup | overshoot [%] | t_ss [s] | time at upper limit (lon) / at either limit (lat) [s] |
|---|---|---|---|---|
| lon 20 m step, v_cmd in [0, 3] | none | 96.6 | never (not settled) | 13.08 |
| lon 20 m step, v_cmd in [0, 3] | back-calculation | 0.4 | 6.84 | 6.48 |
| lon 20 m step, v_cmd in [0, 3] | clamping | 1.3 | 6.80 | 6.62 |
| lat 2 m step, u_lat limit +-1.48 rad/s (linear plant) | none | 84.0 | 4.46 | 1.84 |
| lat 2 m step, u_lat limit +-1.48 rad/s (linear plant) | back-calculation | 3.6 | 2.54 | 0.26 |
| lat 2 m step, u_lat limit +-1.48 rad/s (linear plant) | clamping | 25.3 | 2.86 | 0.50 |

Non-linear plant, 1.5 m lateral step at 2 m/s (no scheduling): without anti-windup the integrator state keeps the steering saturated and the car circles (heading error grows to 35 rad); back-calculation: overshoot 5.6 %, t_ss 2.36 s, max heading error 0.87 rad; clamping: overshoot 44.9 %, t_ss 3.60 s. Back-calculation is therefore the default (clamping is kept as an option).

Note (lon): after the overshoot v_cmd stays at its lower limit 0 (the car cannot reverse), so a residual position overshoot of a few cm cannot be corrected - a physical limit, not windup. Note (lat): the lateral type-2 plant + integrator loop is only conditionally stable under saturation - without anti-windup a 3 m step drives the linear loop with saturation unstable; this is why anti-windup is mandatory here.

## 9. Robustness

Loop-gain multiplier q (Delta_q = Dc Dp + q Nc Np) for which the closed loop stays stable: lon 0.032 ... 8.35 (30.0 dB down / 18.4 dB up), lat 0.309 ... 2.70 (10.2 dB down / 8.6 dB up). Both loops are conditionally stable (type 2/3): too *little* gain is as dangerous as too much, which motivates the speed scheduling below.

|---|---|---|---|---|---|
| unscheduled | 1 | 0.9942 | 0.154 | 24.57 | 9.84 |
| unscheduled | 2 | 0.9608 | 0.750 | 1.20 | 2.10 |

```matlab
% lateral: e = 0 - e_y (+ left), feedforward u_ff = v*kappa/k_delta  (k_delta = pid_lat.k_delta = 1.7281)
g = pid_sched(pid_lat, v, 1);  lim = pid_ulat_limit(v, par);  g.umax = lim;  g.umin = -lim;
[u_lat, st_lat] = pid_step(0 - ey_hat, st_lat, g, v*kappa/pid_lat.k_delta);
delta = lat_inverse(u_lat, v, par);
```
- `pid_step.m` / `pid_init.m` / `pid_prefilt.m` / `pid_prefilt_init.m` / `pid_sched.m` carry `%#codegen`, use fixed-size scalars/struct fields only (state: I, ud, eprev, sat, uun). Code generation itself was not run here (no MATLAB Coder in the container).
- The feedforward gain must be `v*kappa/k_delta` (not `v*kappa`): Gr has DC gain k_delta = 1.728 on the corrected input u_lat.
- Position/CTE inputs come from the LKF estimates; the filtered derivative acts on the estimated error, so noise on e_y at the Nyquist frequency is amplified by |C(-1)| = 67 rad/s per m (lat, v0 = 2 m/s; scheduled gains scale with v0/v) and 30 m/s per m (lon) - check once with the real LKF noise level.
- v < 1 m/s is outside the identified range; `pid_sched` clips v at 1 m/s.

## 12. Caveats

- The lateral t_ss = 2.1 s (target 2.5 s) is close to the limit of what a single PID can achieve on this plant (0.1 s equivalent delay, type 2 + integral action); larger damping slows the loop (Section 3).
- Step metrics are for the prefiltered (2-DOF) loop. The plain 1-DOF loop has large overshoot (lat 64 %, lon 22 %) on reference steps and ~51 % zero-crossing on an initial offset; the prefilter must be engaged for reference steps/initial offsets.
- The lateral linear model assumes constant v; speed changes are covered by gain scheduling and by the lat_input/lat_inverse static map (not by a time-varying proof). Below 1 m/s the identified model is not valid.
- Actuator rate limits (steering servo slew, VESC acceleration) are not modelled beyond the identified linear dynamics.
