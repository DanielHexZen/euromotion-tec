## 1. Setup

* **Track** (`track_prepare.m` -> `track.mat`, `fig/fig_track.png`): `data/MexicoCity.csv`, coordinates and widths x 0.1 (1:10), periodic cubic spline, periodic Gaussian smoothing (0.4 m) with spectral derivatives, re-parametrised by arc length, ds = 0.0499 m, N = 8594 points, **L = 429.0 m** (4290 m full scale), width 0.99-1.77 m. Curvature from spectral derivatives (extra Gaussian 0.3 m), max |kappa| = 0.95 1/m (min radius 1.06 m). Boundaries = centreline +- width along the normal.
* **Speed profile** v_ref(s) = min(v_max_track = 2.5 m/s, sqrt(a_lat/|kappa|) with a_lat = 2.5 m/s^2, steering-feasible speed), cyclic forward (+1.5 m/s^2) and backward (-2.0 m/s^2) acceleration limits (|a_x| <= 2). Time-parametrised reference s_ref(t), v_ref(t) from rest at s = 0: reference lap time 174.1 s, mean 2.5 m/s (min 1.6). The profile is periodic, so the 8 m run-out follows lap 2.
* **Plant** (`nav_plant_step`): identified `Gv` (v(k+1) = 0.911883 v(k) + 0.088206 v_cmd(k)) and `Gr` (3-sample delay) as difference equations, u_lat = lat_input(v, delta); psi' = r, midpoint position integration; saturations 0 <= v_cmd <= 3 m/s, |delta| <= 0.34 rad, **new: steering-servo rate limit 6.98 rad/s (0.15 s per 60 deg, servo specification)** applied to the commanded angle before `lat_input` (servo specification 0.15 s per 60 degrees = (pi/3)/0.15 = 6.98 rad/s; the identified Gr already contains the servo lag, the rate limit only caps fast commands; the controller is not aware of it). Start: at rest, 0.1 m left of the centreline, heading along the path.
* **Sensors** (`nav_sensor_step`, `nav_noise`): a_x = (v(k)-v(k-1))/T, a_y = v r, gyro r, wheel speed v + noise (sigma 0.0072 m/s, in-motion std of 03); 10 Hz position fix (0.05 m) and heading fix (0.02 rad); biases from 03 with random walk. **Noise level (nominal): in-motion levels of 03** (sigma_ax 0.404, sigma_ay 0.584 m/s^2) and the **LKF Q built on exactly that value** (sigma_w = sigma_a_mot = 0.502 m/s^2). 5 s standstill phase (running-mean bias calibration; controllers idle; not in the lap time).
* **Estimator** (`nav_est_step`): complementary heading filter (gain 0.1), accelerations rotated to the global frame, `lkf_fk` + `lkf_step` with the 6-state design of 03. **New (nominal): the optional wheel-speed velocity measurement of 03** (`lkf_design(...,usev=1)`: v_wheel [cos psi; sin psi], R_v = 0.05^2, used at the 10 Hz fix instants, i.e. H has 4 rows). Initial state = true start position, zero velocity.
* **Path projection** (`nav_project`): windowed nearest-vertex search (+-4 m, lap wrap), first-order foot-point refinement -> signed CTE, s_hat, path heading. Estimated position drives the loop; true position is used for all metrics.
* **Controllers** (`nav_lon_step`, `nav_lat_step`, via `pid_step`, gains unchanged):
  * Longitudinal: e_s = s_ref - s_hat, feedforward = plant inverse of Gv on the reference (`ffmode` 2), saturation 0..3 m/s, back-calculation anti-windup.
  * Lateral: gain-scheduled (v0/v_hat), limit lat_input(v, 0.34), curvature feedforward v_hat kappa(s_hat + v_hat t_la)/k_delta with t_la = 0.12 s, prefilter on the initial offset, delta = lat_inverse(u_lat, v_hat). **New D action (`dmode` 2, nominal):** Kd(v0/v) is taken out of `pid_step` and applied on the measurement only, u_D = -Kd(v0/v) d(ey)/dt with d(ey)/dt = (LKF velocity estimate) . n(psi_path) (exact: the foot-point projection gives d(ey)/dt = v.n), added to the feedforward before the saturation (anti-windup still acts on the total). Used above 1 m/s (the lower end of the identified range); during start-up (< 1 m/s) the designed differenced D is used, because with the velocity D the start-up offset of the first second grew to 0.144 m in one seed. No kick at the 10 Hz position-fix jumps.
* a_lat = 2.5 m/s^2 and t_la = 0.12 s are kept from iteration 1. The requested a_lat = 2.2 was tried and is **not needed**: lap time 174.9 s instead of 174.1 s (+0.8 s, +0.5 %), CTE unchanged (max 0.144 -> 0.144 m in the then-worst seed, RMSE 0.024 -> 0.024 m, tested before the start-up switch).

Findings:
* **Steering rate RMS before/after:** iteration-1 design A 2.75 rad/s -> nominal E 0.35 rad/s commanded (0.24 applied after the 6.98 rad/s (0.15 s per 60 deg, servo specification) limit); the limit itself is active in only 0.1 % of the samples (A-B: the 6.98 rad/s (0.15 s per 60 deg, servo specification) limit alone does not change the picture, rate RMS 2.75 commanded / 2.12 applied, CTE_max worst 0.182 m).
* **The velocity-based D alone does not help** (C): with the accelerometer+position LKF the cross-track velocity error (~0.05-0.09 m/s) times the long derivative time Td = Kd/Kp = 0.5 s acts like a 3-4 cm offset, so CTE_max worst 0.237 m, RMSE 0.062 m, although the steering is smooth (0.5 rad/s). The differenced estimated position carries consistent information, the LKF velocity does not.
* **The effective lever is the estimate quality:** adding the wheel-speed measurement that 03 already provides (D) halves the LKF error (0.039 -> 0.018 m), giving CTE_max worst 0.120 m and RMSE_CTE worst 0.022 m (all seeds pass). Together with the measurement-D (E) the steering rate drops a further factor 3 at equal CTE (worst 0.113 m / 0.025 m).
* Caveat of the wheel-speed fusion: it assumes no side slip (projection of the wheel speed on the estimated heading). It holds in this simulation; on the real data 03 found it worse (0.199 m, the car slides in corners), so the nominal result applies to the simulation plant. Design R_v includes a margin (sigma_v = 0.05 m/s).

## 5. Design notes and caveats

1. CTE is estimation-limited; the position error of the accelerometer+fix LKF (~0.04 m) was the main driver of CTE and steering activity in iteration 1.
2. The 6.98 rad/s servo rate limit is the **servo specification** (0.15 s per 60 deg, (pi/3)/0.15); the identified Gr contains the servo lag but no rate limit, and the plant has no servo dead zone.
3. Position fixes are time-aligned with the truth (no latency); the plant is the identified linear model without tyre slip, dead zone or latency beyond the 3 samples; validity is bounded by the identification fit (91-93 %).
4. Sector labels in `fig_nav_zoom.png` are indicative.
5. Other figures: `fig_nav_track.png`, `fig_nav_zoom.png`, `fig_nav_cte.png`, `fig_nav_speed.png`, `fig_nav_steering.png`, `fig_nav_lkf_error.png`, `fig_nav_speed_sens.png`, `fig_nav_seeds.png` (CTE_max and steering rate per seed for A, D, E), `fig_track.png`.

## 6. Simulink model (`build_nav_simulink.m`, `nav_closed_loop.slx`) - status: VERIFIED in MATLAB R2026a

`build_nav_simulink.m` generates the data (same nominal configuration and portable noise as `nav_main` run 1), builds `nav_closed_loop.slx` (fixed-step discrete solver, Ts = 0.02 s), simulates it and compares with the script (`nav_sim`). Structure (`fig/fig_simulink_model.png`): Digital Clock -> StepIdx (k); Reference (track lookup of s_ref, v_ref, v_ref(k+1)); Sensors (From Workspace noise `E_in`); Estimator (calibration + heading filter + `lkf_step`); ProjEst; LonPID; LatPID; Plant (`nav_plant_step`) -> Unit Delay `PlantState` (breaks the loop); ProjTrue (evaluation). All blocks are MATLAB Function blocks calling the same .m functions (`pid_step`, `lkf_step`, `nav_project`, ...), persistent internal states, Parameter-scope data, To Workspace logging.

**Verification (9117 samples):** max |difference| Simulink vs script: position 8.5e-14 m, LKF estimate 4.3e-14 m, steering 2.4e-14 rad, v_cmd 1.9e-12 m/s; CTE identical (CTE_max 0.1015 m, RMSE_CTE 0.0249 m).
