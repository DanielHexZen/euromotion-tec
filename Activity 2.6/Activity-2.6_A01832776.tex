\section{Introduction}
This report covers the position and speed control of the car.
First, the plant is identified from open-loop tests.
Then a PID controller is designed, tuned and discretized in MATLAB/Simulink.
Finally, it runs on the NUCLEO-F446RE.
The car drives a target distance with a trapezoidal speed profile.
It stops at obstacles closer than \(30\,\mathrm{mm}\) and receives new parameters via Bluetooth.

The encoders measure the wheel speed.
The team ran two test sessions.

\section{Model Identification}
Input \(u\) is the PWM duty in \%. Output \(v\) is the wheel speed in mm/s.
The model is first order with dead time:
\begin{equation}
  G(s) = \frac{V(s)}{U(s)} = \frac{K\,e^{-Ls}}{\tau s + 1}
\end{equation}
\texttt{identify\_car} identifies it in three steps:
\begin{enumerate}
  \item Each step is fitted with \(v(t) = V_{ss}\bigl(1 - e^{-(t-L)/\tau}\bigr)\) for \(t > L\)
        (least squares, \texttt{fminsearch}).
  \item The steady-state speeds give a line per wheel, \(V_{ss} = K\,(u - u_0)\) (\texttt{polyfit}).
        \(K\) and \(u_0\) are the mean of both wheels.
  \item \(\tau\) and \(L\) are the median of the steps above 40\,\% of the top speed.
\end{enumerate}
Result:
\begin{itemize}
  \item \(K = 7.596\,\mathrm{(mm/s)/\%}\), slope of the steady-state speed over duty.
  \item \(\tau = 50\,\mathrm{ms}\), time constant.
  \item \(L = 0\), no measurable dead time.
  \item Dead zone \(u_0 = 7.0\,\%\): \(v_{ss} = K\,(u - u_0)\) for \(u > u_0\).
\end{itemize}
% TODO: load the step data into the System Identification app (process model P1D),
%       add the screenshot and the fit value.
As a cross-check, the MATLAB System Identification app reaches a fit of [TBD]\,\%.
The position is the integral of the speed:
\begin{equation}
  X(s) = \frac{G(s)}{s}\,U(s)
\end{equation}
Check on the floor: at 60\,\% duty the model predicts 403 mm/s, the car reached 374 mm/s.
The load lowers the gain by about 7\,\%.
The simulation therefore also tests a gain of \(\pm 20\,\%\).

\section{Control Loop Simulation}

\subsection{Closed Loop Model}
The loop is a cascade, the same as in the firmware.
A position loop corrects the speed command, a PI controls the speed.
% TODO: build the Simulink model and add the screenshot.

\begin{itemize}
  \item \textbf{Reference generator:} trapezoidal speed profile.
        The user sets the distance \(D\), the speed \(v_{max}\),
        the acceleration time \(t_a\) and the deceleration time \(t_d\).
  \item \textbf{Position controller:} P, \(K_{px} = 2\,\mathrm{s^{-1}}\),
        correction limited to \(\pm 100\,\mathrm{mm/s}\).
  \item \textbf{Feed-forward:} inverse of the static map, \(K_{ff} = 1/K = 0.1316\,\%/(\mathrm{mm/s})\),
        plus an acceleration term.
  \item \textbf{Speed controller:} PI, integral limited to \(\pm 30\,\%\) (anti-windup).
  \item \textbf{Actuator model:} BTS7960 H-bridge. Duty limited to \(\pm 100\,\%\), dead zone \(u_0 = 7\,\%\).
  \item \textbf{Plant:} \(G(s)\) from the identification.
  \item \textbf{Sensor model:} encoder with \(k_x = 0.0636\,\mathrm{mm/count}\) (quantizer),
        speed from the count difference over \(T_s\), IIR filter with \(\alpha = 0.5\).
\end{itemize}

Reference profile:
\begin{equation}
  v_{ref}(t) =
  \begin{cases}
    v_{max}\,\dfrac{t}{t_a}       & 0 \le t < t_a \\[4pt]
    v_{max}                        & t_a \le t < T - t_d \\[4pt]
    v_{max}\,\dfrac{T - t}{t_d}   & T - t_d \le t \le T
  \end{cases}
\end{equation}
\begin{equation}
  T = \frac{D}{v_{max}} + \frac{t_a + t_d}{2},
  \qquad
  x_{ref}(t) = \int_0^t v_{ref}(\tau)\,d\tau
\end{equation}
If \(D\) is too short to reach \(v_{max}\), the profile is a triangle with
\(T = t_a + t_d\).

Control law:
\begin{align}
  v_{cmd} &= v_{ref} + \mathrm{sat}_{\pm 100}\bigl(K_{px}\,(x_{ref} - \hat{x})\bigr) \\
  e_v     &= v_{cmd} - \hat{v} \\
  u       &= u_0\,\mathrm{sgn}(v_{cmd}) + K_{ff}\,v_{cmd} + K_{ff}\,\tau\,a_{ref}
             + K_p\,e_v + K_i \int e_v\,dt
\end{align}
Sensor:
\begin{equation}
  \hat{x}[k] = k_x \left\lfloor \frac{x[k]}{k_x} \right\rfloor,
  \qquad
  \hat{v}[k] = \hat{v}[k-1] + \alpha \left( \frac{\hat{x}[k] - \hat{x}[k-1]}{T_s} - \hat{v}[k-1] \right)
\end{equation}

\subsection{Continuous Simulation}
The continuous PID is:
\begin{equation}
  C(s) = K_p + \frac{K_i}{s} + K_d\,s
\end{equation}
With \(K_d = 0\) (Section~\ref{sec:tuning}) it is a PI.
The continuous simulation runs the controller every 0.1 ms with the true speed.
Gains from Section~\ref{sec:tuning}.
\begin{itemize}
  \item Speed step: no overshoot, settled (5\,\%) after 0.31 s.
  \item 1000 mm at 300 mm/s, ramps of 1 s: final error \(-0.38\) mm, largest position error 0.38 mm.
\end{itemize}

\subsection{Discretization}
The sampling time is \(T_s = 20\,\mathrm{ms}\) (TIM6 interrupt, 50 Hz). Reasons:
\begin{itemize}
  \item \textbf{Speed resolution.} One encoder count per sample is
        \(k_x / T_s = 3.18\,\mathrm{mm/s}\) at 20 ms, but 12.7 mm/s at 5 ms.
        A shorter \(T_s\) makes the speed signal too coarse.
  \item \textbf{Fast enough.} The closed speed loop rises in about 0.2 s.
        That gives about 10 samples per rise time (rule of thumb: 4 to 10).
  \item \textbf{Cost.} Sampling and filter add a delay of
        \(\theta = T_s + \tau_f = 49\,\mathrm{ms}\) (\(\tau_f = 28.9\,\mathrm{ms}\)).
        The tuning includes this delay.
\end{itemize}
The plant is discretized with a zero-order hold.
The sensor is discrete by nature (count difference and IIR filter):
\begin{equation}
  \frac{\hat{V}(z)}{X(z)} = \frac{z - 1}{T_s\,z} \cdot \frac{\alpha\,z}{z - (1 - \alpha)}
\end{equation}
The discrete PI uses the forward Euler integral, as in the firmware:
\begin{equation}
  C(z) = K_p + \frac{K_i\,T_s}{z-1}
  \quad\Leftrightarrow\quad
  u[k] = K_p\,e[k] + I[k-1], \qquad I[k] = I[k-1] + K_i\,T_s\,e[k]
\end{equation}

\subsection{Tuning}\label{sec:tuning}
The PI gains follow the SIMC rules (Skogestad), with the delay \(\theta\) from above:
\begin{equation}
  K_p = \frac{\tau}{K(\tau_c + \theta)}, \qquad
  T_i = \min\bigl(\tau,\ 4(\tau_c + \theta)\bigr), \qquad
  K_i = \frac{K_p}{T_i}
\end{equation}
The closed-loop time constant \(\tau_c\) sets the speed of the loop.
Three settings were compared:

\begin{table}[H]
  \centering
  \caption{SIMC settings (speed step, design model).}
  \begin{tabular}{@{}lccccc@{}}
    \toprule
    \textbf{Setting} & \(\tau_c\) & \(K_p\) & \(K_i\) & \textbf{Overshoot} & \textbf{Settling (5\,\%)} \\ \midrule
    Tight    & \(\theta\)  & 0.067 & 1.347 & 4.1\,\% & 0.16 s \\
    Balanced & \(2\theta\) & 0.045 & 0.898 & 0.0\,\% & 0.31 s \\
    Gentle   & \(4\theta\) & 0.027 & 0.539 & 0.0\,\% & 0.62 s \\ \bottomrule
  \end{tabular}
\end{table}

\emph{Balanced} was chosen: no overshoot and still fast.
Tight overshoots, and a real gain change makes it worse.
\(K_d = 0\). A derivative term would amplify the speed quantization of 3.18 mm/s.

\section{Firmware Implementation}

\subsection{Sampling Period}
TIM6 runs at \(f_{TIM6} = 90\,\mathrm{MHz}\) (APB1 \(45\,\mathrm{MHz} \times 2\)).
With PSC \(= 8999\) and ARR \(= 199\):
\begin{equation}
  f_s = \frac{f_{TIM6}}{(PSC+1)(ARR+1)} = \frac{90\cdot 10^6\,\mathrm{Hz}}{9000 \cdot 200} = 50\,\mathrm{Hz}
\end{equation}
\begin{equation}
  T_s = \frac{1}{f_s} = 20\,\mathrm{ms}
\end{equation}

\subsection{PWM Signal}
% TODO: check APB2 timer clock and PSC/ARR of TIM1 in the .ioc file.
TIM1 generates the PWM for both H-bridges at \(20\,\mathrm{kHz}\).
\begin{equation}
  f_{PWM} = \frac{f_{TIM1}}{(PSC+1)(ARR+1)}
\end{equation}
\begin{equation}
  (PSC+1)(ARR+1) = \frac{180\cdot 10^6\,\mathrm{Hz}}{20\cdot 10^3\,\mathrm{Hz}} = 9000
\end{equation}
\begin{equation}
  \text{Duty} = \frac{CCR}{ARR+1} \cdot 100\,\%
\end{equation}
Used values: PSC \(=\) [TBD], ARR \(=\) [TBD].

\subsection{Distance and Speed}
Each encoder gives \(N_{rev} = 3584\) counts per wheel revolution (x4 decoding).
The wheel circumference is \(C_w \approx 228\,\mathrm{mm}\).
\begin{equation}
  k_x = \frac{C_w}{N_{rev}} = \frac{228}{3584} \approx 0.0636\,\mathrm{mm/count}
\end{equation}
\begin{equation}
  x[k] = k_x\,N[k],
  \qquad
  v[k] = \frac{x[k] - x[k-1]}{T_s}
\end{equation}
The speed resolution is \(k_x / T_s \approx 3.18\,\mathrm{mm/s}\).

\subsection{PID Algorithm}
The PID runs in the TIM6 callback, every \(T_s\):
\begin{align}
  e[k] &= r[k] - y[k] \\
  I[k] &= I[k-1] + K_i\,T_s\,e[k] \\
  u[k] &= K_p\,e[k] + I[k] + K_d\,\frac{e[k] - e[k-1]}{T_s}
\end{align}
The output is limited to \(\pm 100\,\%\) duty.
When the output saturates, the integral stops (anti-windup).

\begin{verbatim}
TIM6 callback (every 20 ms):
  read encoders            -> x, v
  next reference point     -> x_ref, v_ref
  if obstacle: hold reference, duty = 0
  else:        PID -> duty -> CCR (TIM1)
\end{verbatim}

\subsection{Obstacle Detection}
The ultrasonic sensor measures the echo time \(t_{echo}\).
With the speed of sound \(c = 343\,\mathrm{m/s}\):
\begin{equation}
  d = \frac{c\,t_{echo}}{2}
  \;\Rightarrow\;
  d\,[\mathrm{mm}] = 0.1715 \cdot t_{echo}\,[\mu\mathrm{s}]
\end{equation}
If \(d \le 30\,\mathrm{mm}\), the motors stop and the reference is held.
When the obstacle is removed, the car continues the profile.
